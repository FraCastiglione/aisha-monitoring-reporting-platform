# Project Dashboard status and data

The signed AISHA Grant Agreement is the source for formal project start, 48-month calendar, Work Package and Task assignments, deliverables, milestones, the 17 potential risks and KPI targets. The coordinator-confirmed voluntary associated-partner commitments in Attachment 6 supplement Task reporting routes without changing Annex 1. The separate `dashboard-data.json` stores the coordinator's status updates, published messages and reviewed measurements. The September 2026 seed records three deliverables as **submitted** and five milestones as **achieved**, as reported by the user; it does not claim formal acceptance or independent evidence verification. `status_as_of` preserves when those facts were last supplied, even if a later intake candidate advances its preparation date and project calendar month.

## Status and reporting coverage

The private register uses `not_started`, `draft`, `submitted`, `changes_requested`, `resubmitted`, and `accepted` for a **whole partner Task report**, identified by `{partner}:TASKS:{start}:{end}`. The coordinator's `compile-dashboard.mjs` accepts only the registered revision of a structurally valid JSON file and writes a private candidate. It counts unconfirmed files and stops if two accepted reports cover the same partner, Task and selected month. The published dashboard file receives the candidate only after human review. The private coordinator tools and intake instructions are not included in this public repository.

Each sanitized `reporting_records` entry is either `kind: "task"` or `kind: "work_package"` and contains its Agreement ID, partner code, whole-report receipt status, completed/no-work declaration, and exact coverage dates and selected months. A Work Package summary aggregates its partners' **assigned Task entries** and displays the Work Package leader's own leadership update separately. A leader's assessment of another partner's Task is never counted as that partner's report. Records can cover only some months or days of the chosen dashboard window. An eligible partner without a matching record is **No report recorded**, not automatically late or incomplete: the dashboard has no formal monitoring-request scope or prior-report history beyond the supplied collection.

## Risks and indicators

The 17 Agreement risks are potential risks, with their original impact, likelihood and related Work Packages. Their card mitigations are labelled as summaries; they are not the full signed risk wording. They do not automatically flag each Task in those Work Packages. `task_flags` contains coordinator flags, at-risk/delayed Task assessments from accepted Work Package leader updates, or medium/high/critical significant issues from accepted partner Task reports. Narrative details stay private. The dashboard keeps these distinct.

Agreement KPI targets are shown without invented actuals. The catalogue now includes the objectives and dissemination indicators from PDF pp. 113–115 and 137–138. Their conflicting dissemination reach, women-beneficiary and DSJP timing figures are displayed together with source notes until the coordinator defines the measurement basis. Partner files may include typed `kpi_contributions` with evidence references and self-reported Nextcloud proof status. `kpi_values` accepts reviewed project totals and optional partner breakdowns by matching KPI ID; importing a partner file never updates public actuals automatically. Text narratives are not converted to counts. Partner values should not simply be summed for unique people, audiences, media items, shared activities or rates; deduplication and numerator/denominator checks occur before adding a project total. No missing measurement is displayed as zero.

The preview has no Nextcloud sync or automatic public publication. Sensitive deliverable contents, contributor contacts and report narratives remain outside the dashboard snapshot.

## Agreement detail and planning calendar

The dashboard reads full Work Package objectives and Task wording from `assets/agreement-content.js`. Deliverable descriptions and milestone means of verification are transcribed from Annex 1 into `assets/dashboard-detail.json`. The overview's totals use all 22 Agreement deliverables and 23 milestones; its upcoming list covers the six project months after the snapshot month and includes scheduled Task and Work Package starts.

The Gantt uses the Agreement's month-level activity windows and due months. It supports each calendar year, a full 48-month view and an expanded display. The calendar places deliverables and milestones on the final day of their due month **for display only**: the Agreement gives a project month, not an exact day. The first of the due month is the coordinator's internal draft review checkpoint, not a contractual date. It applies to outstanding deliverables and milestones due in that month; already submitted or achieved items retain their due-month marker but no future draft checkpoint. A future `task_report_deadlines` entry may supply a coordinator-set `id`, exact `due_date` and optional `partner`; the array is empty until a monitoring schedule is agreed. A Task report due on the first of a month gets a draft checkpoint on the first of the prior month. Existing Task report records are shown as coverage for a month, never assigned an invented receipt date.

The message board reads the `messages` array in `dashboard-data.json`. Each published message may include `date`, `title`, `body`, `author`, `priority` (`urgent`, `important`, or standard) and an optional HTTPS link. The public site is read-only: the coordination team publishes changes by updating the dashboard data and deploying the site. The seed contains no fabricated announcements.

Work Package cards count Tasks that have at least one coordinator-confirmed partner entry. This is reporting coverage, not implementation completion. Verified Task completion is shown only from optional, reviewed `task_progress` entries with state `completed`; without such entries, completion remains **Not assessed**. Deliverable submission and milestone achievement do not automatically complete an ongoing Task or Work Package.
