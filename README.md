# AISHA monitoring and reporting platform

This is a [public static site](https://fracastiglione.github.io/aisha-monitoring-reporting-platform/). Partners can prepare one report containing several Tasks and Work Packages across selected project months, or prepare a separate Communication & Dissemination check-in. Nothing is sent from the site to a server. The requested two-week communication check-in is a coordinator workflow choice from the project brief; it is not presented as a Grant Agreement deadline.

## Open the preview

The local preview is available at `http://localhost:8765/` while its server is running. To start it again from this folder, run `python3 -m http.server 8765`. No build step or account is required.

The public dashboard and KPI catalogue use `assets/embedded-data.js` so they also load in browsers that cannot fetch the site's JSON files after opening the page. Whenever `dashboard-data.json`, `assets/dashboard-catalogue.json`, or `assets/dashboard-detail.json` changes, run `python3 scripts/embed-data.py` before publishing. The PDF generator similarly uses bundled font and logo bytes; after changing either asset, run `python3 scripts/embed-pdf-assets.py`. The source files remain editable; the generated scripts are their public-page copies.

## Partner Task report

A partner drags across the M01–M48 timeline to add months. Further drags add other ranges without clearing earlier selections, including ranges separated by gaps; individual clicks omit or restore a month. Keyboard users can toggle months with Enter or Space. All project months can be selected, including future months for planning. The first and last dates follow the selected outer months. The report stores the selected month list, so gaps are excluded even when they fall between its start and end dates. Eligible Tasks must be assigned to that partner and active in at least one selected month. The partner can narrow coverage dates for each Task; excluded months remain excluded. The site has no knowledge of earlier submitted reports. When the timeline changes, coverage bounds are adjusted to available dates; an expanded completed Task returns to draft for review.

The Agreement assigns T1.3 to all beneficiaries and all associated partners; ADRA is additionally named in T3.1. Attachment 6 adds further voluntary Task commitments, including all 32 Tasks for AD, BOSCH, CEPS, EPRD and RT as confirmed by the coordinator. Their Task form omits cost inputs, and imported files containing associated-partner cost entries are rejected because associated partners may not charge costs to the action.

Adding a Task opens it as an unfinished draft. Returning without entering anything removes that new Task; returning with answers preserves it as a draft. “Mark Task report complete” marks an entered contribution complete, while “Declare no work carried out” records an explicit no-work response from either the overview or editor. Unfinished Tasks must be completed, marked no work, or removed before final generation. Narrative and cost fields are optional. If a significant issue is marked Yes, severity is required; a requested coordinator action needs a description. An individual Task PDF can be downloaded from the editor or from a completed Task card. It is labelled as an individual report, and an unfinished contribution remains visibly marked as a draft of the full report. One final review step and one PDF/JSON pair cover all completed or no-work Tasks and Work Package leadership updates. The report key is `{partner}:TASKS:{start}:{end}`; changing the selected months for the same date bounds is a correction to that report and should use a higher revision if it has already been sent. This monitoring workflow is a product design, not a reporting cadence prescribed by the Agreement.

## Drafts and privacy

A partner can explicitly save one current browser draft per partner/report type, open a download dialog for a readable PDF draft and an editable JSON draft, restore the browser copy, or delete it from the restore dialog. The PDF draft embeds the editable data so this preview can reopen it. The browser draft contains the whole Task report, including Work Package leadership updates, additional voluntary contributions and direct KPI values. Work Package leaders can report on coordination of their Agreement-assigned Work Packages and assess each active Task in that Work Package; this stays distinct from their organisation’s own Task contributions. A partner can generate a report containing only a Work Package leader update. Typical text reports are small enough for browser storage; quotas vary and can be cleared. If a browser save fails, the site says so and the downloaded draft remains available. JSON imports are limited to 5 MB. New AISHA-generated PDFs (up to 10 MB) embed structured answers and can also be imported. The whole-report import below the timeline lets a partner select individual Task, Work Package leadership, additional contribution and KPI entries from a complete report or draft. When the file uses the current selected months, unselected entries stay; a different period adopts the file’s timeline and replaces current entries. Each Task also has its own individual-PDF import, which accepts only that Task and preserves all other entries. A matching JSON file is needed for older PDFs without embedded data; arbitrary PDF text cannot be reliably mapped into fields. The full Agreement wording is bundled with the site and is not duplicated in each draft.

The generated PDF and JSON contain the same reviewed answers. Generating them is not evidence of submission. Partners manually transfer both files through the agreed AISHA channel. The site has no Nextcloud access or automatic upload.

Direct KPI entry and suggestions are currently paused in both report builders. Existing KPI values in older draft/report files remain validated, importable and preserved in review/export. A shared activity code remains available on communication events for coordinator deduplication. These records do not update public KPI totals by themselves.

The Project Dashboard shows the Grant Agreement schedule, the coordinator-reported late-September 2026 deliverable and milestone updates, all 17 baseline risks, nine SMART objectives, the 19-row call KPI measurement table, 24 communication table rows, 13 measurement-framework blocks, 26 additional measurement passages and 114 typed reportable fields, and Task, Work Package and partner reporting rosters. Its headline totals open complete deliverable and milestone lists with Agreement descriptions or means of verification and linked Tasks. The Work Packages view displays every package's exact Agreement objectives and Task descriptions with clearer formatting. The Gantt shows the 48 project months plus M49–M50 for final report closeout, with a linked calendar, first-day internal draft markers, month-end deadline markers, and three Technical Progress Report preparation windows (M19–M20, M37–M38, M49–M50) shown as upper and lower rails around relevant Work Package and Task activity bars. These review windows are coordinator planning months without artificial date deadlines; the project duration remains 48 months. The 20–21 May 2026 kickoff at La Sapienza facilities in Rome and the 18–19 November 2026 Brussels consortium meeting appear in the month headers and calendar agenda. Coordinator-scheduled Task report deadlines and recorded report coverage appear when supplied. The dashboard offers six reference tables with exact Agreement passages, PDF and printed Part A/B page references, related Tasks, and indicator search/favourites. New KPI values cannot be entered in the reporting forms. The message board reads published updates from `dashboard-data.json`; there are no invented messages. Partner-report coverage, verified Task completion and KPI actuals remain unassessed or empty until reviewed information is supplied. Private coordinator tools validate collected whole-partner JSON files, prepare a KPI review queue and produce a sanitized dashboard candidate; submissions, status registers and review output are not included in this public repository. See [dashboard data rules](docs/status-and-dashboard.md) for the distinction between potential risks, actual Task flags, and missing report records.

Original Agreement passages remain verbatim; interpretation notices are currently hidden by coordinator request. This does not reconcile differences between source passages. Optional coordinator monitoring rounds and a registry of shared activity codes can be added to `dashboard-data.json` when announced; both lists are empty today. A monitoring round can preselect its defined months in the partner timeline, but the partner may still select months independently.
